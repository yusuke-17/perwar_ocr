# senzen_word の漏れ・誤変換調査

調査日: 2026-11-03
対象: `pkg/senzen_word`（v0.2.0）と、それを呼ぶ `utils/text_normalizer.py`

## 調べ方

- ソース（kanji / kana / hentaigana）と辞書 JSON を全部読んだ
- NDLOCR-Lite の出力文字集合（`vendor/ndlocr-lite/src/config/NDLmoji.yaml`、7,141字）と辞書を突き合わせた
  → 「OCR が出しうるのに、変換されずに残る旧字・記号」を洗い出す
- Unicode 公式の Unihan データ（常用・人名用漢字の一覧と異体字の対応）を基準にした
- 実際の文例で変換を動かし、取りこぼしと誤変換を確かめた

前提: パイプライン（`normalize_text` / `normalize_query`）は senzen_word の前に NFKC をかける。
そのため互換漢字（`海` U+FA45 など）と `ゟ`→より・`ヿ`→コト は NFKC が先に処理している。

## 結果の要約（優先度順）

| # | 種類 | 内容 | 影響 |
|---|---|---|---|
| 1 | 漢字の漏れ ✅ | `敎說內歲產尙` など字形違いの旧字が辞書に無い（2026-11-03 に G10 で対応） | 本文に旧字が残る。「教育」で検索しても「敎育」の文書が当たらない |
| 2 | 仮名の誤変換 | `きやう`→`きよう`（正: きょう）、`でう`→`ぢょう`（正: じょう） | 誤った現代仮名になる |
| 3 | 仮名の誤変換 | 語の境目をまたいで変換する（`という`→`とゆう`、`これはうそ`→`これほうそ`） | ひらがな文・戦後文書で壊れる |
| 4 | 助詞の取りこぼし | カタカナ送り仮名の直後の助詞を変換しない（`有スルノ`、`國民ニハ`） | 漢字カタカナ交じり文で半分しか変わらない |
| 5 | 記号の漏れ | 踊り字 `ゝゞヽヾ〻〱〳〴〵` を扱わない | OCR の文字集合に含まれるのに残る |
| 6 | 表記の方針 | カタカナの長音を `ー` にする（`カウシテ`→`コーシテ`） | 和語に `ー` は不自然。ひらがな側（`こう`）と揃わない |
| 7 | テスト | 必ず通ってしまうテストがある | 不具合を見逃す |

## 1. 漢字（旧字体→新字体）

> **対応済み（2026-11-03）**: G10 で変換表を 533 字に拡充し、監査ツールを追加した。詳細は `openspec/changes/archive/2026-11-03-g10-kanji-variant-table/`

### 1-1. 辞書の状態

- 常用 372 + 人名用 9 + 異体字 3 = 384字。変換先はすべて常用・人名用漢字で、データの誤りは見つからなかった
- 常用表の 372字のうち 62字は互換漢字（`海` など）。パイプラインでは NFKC が先に処理するので、実際に効くのは残りの 310字

### 1-2. 辞書に無い旧字（すべて NDLOCR-Lite の出力文字集合に含まれる）

常用漢字表は「字体の違い」だけを括弧書きの旧字体に載せ、「字形（デザイン）の違い」とみなした字は載せていない。
しかし Unicode では別の文字なので、戦前の印刷物では旧字として現れる。

**A. 追加推奨（字形違いの旧字、迷いが少ない）**

```
敎→教  說→説  脫→脱  銳→鋭  悅→悦  閱→閲  歲→歳  絕→絶
吳→呉  娛→娯  戶→戸  內→内  尙→尚  產→産  姬→姫  旣→既
淸→清  靑→青  鬪→闘  彥→彦  强→強  揷→挿  敘→叙  澀→渋
獎→奨  戱→戯  吿→告  查→査  冰→氷  劒→剣  噐→器  囘→回
姊→姉  鄰→隣
```

**B. 追加候補（俗字・略字。戦前の文書で見かけるが、方針を決めてから）**

```
塲→場  寳→宝  舘→館  竒→奇  刋→刊  畧→略  蘆→芦  豬→猪
```

**C. 方針の判断が要るもの（人名・地名）**

- `嵜` `碕`（崎）、`嶋`（島）、`冨`（富）、`峯`（峰）、`埜`（野）、`凉`（涼）、`駈`（駆）、`盃`（杯）、`薗`（園）
- 今の `variants.json` は `﨑→崎` `髙→高` を変換しているが、この2字は NDLOCR-Lite の文字集合に無く、OCR からは出てこない。
  逆に OCR が出す `嵜` `碕` は変換しない。方針（人名の異体字を揃えるか残すか）を決めて一貫させたい

**入れないもの**: `个从价决` などの簡体字（OCR の誤読の可能性が高い）、`慾→欲` のような「同音の漢字による書きかえ」（字体ではなく語の置き換え）。

### 1-3. ライブラリ単体で使うときの漏れ

互換漢字のうち、NFC で統合漢字に戻るのに辞書に無いものが 940字ある（`晴` U+FA12 など）。
パイプラインでは NFKC で処理済みなので問題にならないが、PyPI で単体利用されると残る。
→ `unicodedata.normalize("NFC", ...)` を互換漢字にだけ当てれば辞書を手で増やさずに済む（標準ライブラリなので外部依存ゼロは保てる）。

## 2. 歴史的仮名遣い（`kana/historical.py`）

### 2-1. 誤変換（直したい）

| 入力 | 今の出力 | 正しい出力 | 原因 |
|---|---|---|---|
| きやう（京） | きよう | きょう | 開拗長音（`きやう` `しやう` `ちやう` …）の規則が無く、`やう`→`よう` だけが当たる |
| キヤウ / シヤウ | キヨー / シヨー | キョウ / ショウ | 同上 |
| でう（條） | ぢょう | じょう | 現代仮名遣いでは連濁・同音連呼以外は「じ」。`でう`/`デウ`/`ぢう`/`ヂウ` の変換先が誤り |

### 2-2. 語の境目をまたぐ誤変換

単純な文字列置換なので、助詞と次の語の頭がつながると誤変換する。

| 入力 | 出力 |
|---|---|
| という | とゆう |
| してしまう | してしもう |
| 向かう | 向こう |
| これはうそ | これほうそ |
| 庭にうゑる | 庭にゅうえる |
| 東へうつる | 東ひょうつる |

戦前の文書は「といふ」「しまふ」と書くので、多くは戦後の文書やひらがな文で起きる。
特に `いう→ゆう` は「言う」と衝突しやすい。前の文字に条件を付ける（助詞 `は に へ が と` の直後では変換しない等）か、外すことを検討。

### 2-3. 対応していない主な型（参考）

- ハ行転呼（`云フ`→`云ウ`、`從ヒ`→`従イ`、`思ハレ`→`思ワレ`）: 最頻出だが、助詞の `ハ` `ヘ` や語頭の `ふ`（ふね）と区別できない。
  文字規則ではなく「漢字＋送り仮名」の単語辞書（`云フ` `從ヒ` `伴ヒ` `行フ` …）にすれば安全に一部を拾える
- `けふ`→`きょう`（今日）など `〜ふ` の長音: `かふ`（買ふ）と衝突するので個別の語に限るべき
- `くわ`→`か`（通常サイズの「わ」）: `加わる` と衝突する

### 2-4. 表記の方針

カタカナの長音を `ー` にしている（`カウ`→`コー`、`テフ`→`チョー`）。
現代の表記では和語・漢語のカタカナに `ー` は使わない（`コウ`）。ひらがな側は `こう` なので、検索で揃わない原因にもなる。

### 2-5. 細かい点

- 置換を規則の順に全文へ繰り返すため、前の規則の出力が後の規則に入る（`くゎう`→`かう`→`こう` は意図どおりだが、規則追加時に連鎖に注意）
- `find_historical_kana` は元の文字列を1回だけ探すので、連鎖した変換は検出結果に出ない

## 3. カタカナ助詞（`kana/katakana_particle.py`）

### 3-1. 取りこぼし

「前の文字がカタカナなら変換しない」規則のため、漢字カタカナ交じり文の送り仮名の後ろでは一切変換されない。

| 入力 | 出力 |
|---|---|
| 有スルノ義務 | 有スルノ義務（変化なし） |
| 爲スヲ以テ | 爲スヲ以テ |
| 國民ニハ | 國民ニハ |
| 法律ニヨリ | 法律ニヨリ |
| 米國ヘノ | 米國ヘノ |
| ナルモノトス | ナルモノトス |

一方で `又ハ`→`又は`、`ト雖モ`→`と雖も` は変換されるので、同じ文書の中で混在する。

### 3-2. 中途半端な変換

複合助詞は後ろの文字を見ないため、長い語の一部だけ変わる。

- `ヨリテ` → `よりテ`
- `ノミナラズ` → `のみナラズ`

### 3-3. 足りない助詞

- 単一: `デ` `カ` `ヤ`（`東京デ` `是カ非カ` が残る）
- 複合: `ニハ` `ニモ` `ニヨリ` `ヘノ` `トノ` `ノミナラズ` `ナド`

### 3-4. 踊り字がカタカナ扱いされない

カタカナの範囲が `ァ-ヶ ー` だけで、`ヽ` `ヾ` を含まない。`コヽニ` → `コヽに` のように、語の途中の `ニ` を助詞と誤認する。

## 4. 記号・踊り字（新しい層の候補）

NDLOCR-Lite の文字集合に含まれるのに、どの層も扱っていない。

| 記号 | 意味 | 変換案 |
|---|---|---|
| `ゝ` `ヽ` | 直前の仮名の繰り返し | `ことゝ`→`ことこ`、`コヽ`→`ココ` |
| `ゞ` `ヾ` | 直前の仮名の濁音で繰り返し | `タヾ`→`タダ` |
| `〻` | 漢字の繰り返し | `各〻`→`各々` |
| `〱` `〳〴〵` | くの字点（縦書きの繰り返し） | 直前の2文字以上の繰り返し。範囲の判定が要るので後回し可 |
| `ゟ` `ヿ` | 合略仮名（より・コト） | パイプラインは NFKC で処理済み。ライブラリ単体のために入れてもよい |

## 5. テスト

- `test_kana_particles.py::test_single_not_in_katakana` の `assert "ノ" in result or "の" in result` は常に真で、何も検証していない
- `test_convert.py::test_all_layers` の `"にて" in result or "に" in result` も弱い
- 「変換してはいけない例」（`という` `向かう` など）のテストが無い

## 6. 関連して見つけたこと（senzen_word の外）

- `text_normalizer.py` の NFKC は単独の濁点 `゛`（U+309B）を「空白＋結合濁点」に分解する。`ハ゛` → `ハ ゙` となり、空白が混ざる。
  NDLOCR-Lite の文字集合に `゛` `゜` があるので、OCR が出すと起きる
- NDLOCR-Lite の文字集合に Unicode の変体仮名は無い。変体仮名の層は既定エンジンでは働かない（GLM-OCR 用）

## 進め方の案

1. 漢字の追加（1-2 の A）とテスト追加 … 小さく安全。検索の当たりが直接よくなる
2. 仮名の誤変換の修正（2-1）と `ー` の方針見直し（2-4）
3. 踊り字の層を追加（4）
4. 助詞の取りこぼし（3）と境目の誤変換（2-2）… 規則の設計が要るので OpenSpec の変更として起こす
