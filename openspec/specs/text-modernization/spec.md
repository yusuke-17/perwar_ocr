# text-modernization Specification

## Purpose

正規化済みの戦前の文章を LLM で現代の口語体に書き換えるときの振る舞いを定める。長い文章を LLM に渡せる大きさに分ける方法と、
LLM に渡さずに残す行の扱いを定め、`prewar ocr` と `prewar fix` のどちらから使っても原文の字が増えたり、欠けたページの前後がつながったりしないことを保証する。

## Requirements

### Requirement: 分割で原文に字を足さない
システムは長い文章を LLM に渡す断片に分けるとき、原文に無い字（句点など）を加えてはならない（MUST NOT）。
断片を順につなぐと、分ける前の文章と一字も違わないものにならなければならない（SHALL）。

#### Scenario: 句点で終わらない長文
- **WHEN** 「。」で終わらない 2,000 字を超える旧字体・カタカナ文語の文章を口語化する
- **THEN** LLM に渡る最後の断片の末尾に「。」は付かない

#### Scenario: 変換に失敗した断片が原文のまま残る
- **WHEN** 「。」で終わらない長文の最後の断片だけ LLM の呼び出しに失敗する
- **THEN** 口語化テキストの末尾にはその断片の原文がそのまま残り、原文に無い「。」は付かない

### Requirement: 目印の行を変換しない
システムは読み取れなかったページの目印の行を LLM に渡してはならず（MUST NOT）、口語化テキストの同じ位置に一字も変えずに残さなければならない（SHALL）。
目印の前の本文と後の本文を同じ断片に入れてはならず（MUST NOT）、目印の行の前後の空行は残さなければならない（MUST）。

#### Scenario: 途中に目印がある
- **WHEN** 文の途中で途切れた本文、「〔第2頁 読み取り失敗（IMG_0002.png）〕」、文の途中から始まる本文の順に並ぶ文章を口語化する
- **THEN** 目印の前後の本文は別々の LLM 呼び出しで変換され、口語化テキストには変換後の前の本文、空行、目印の行、空行、変換後の後の本文の順に並ぶ

#### Scenario: 目印を含むテキストを後から変換する
- **WHEN** 目印を含む OCR 生テキストのファイルを `prewar fix` で口語化する
- **THEN** 目印の行は一字も変わらずに残り、目印をまたいで 1 つの断片にはならない

#### Scenario: 目印だけの文章
- **WHEN** 本文が目印の行だけの文章を口語化する
- **THEN** LLM は呼び出されず、目印の行がそのまま口語化テキストになる

### Requirement: お手本の混入を見つけてお手本なしで変換し直す
システムは口語化した断片の結果に、LLM に渡したお手本由来の語が含まれ、かつその断片の原文に対応する語が無いとき、その結果を採用してはならない（MUST NOT）。
設定 `chunk.retry_without_examples`（既定 true）が有効なら、その断片をお手本を渡さずに 1 回変換し直し、その結果を判定せずに採用しなければならない（SHALL）。
最初の変換はお手本つきで行わなければならない（SHALL）。変換し直したことは画面に知らせなければならず（SHALL）、記録の `meta.json` に何も足してはならない（MUST NOT）。

#### Scenario: お手本つきの結果に混入する
- **WHEN** 話の途中から始まるカタカナ文語の断片（例「是ニ於テ其ノ夜師ヲ訪ネテ教ヲ乞フ。」）のお手本つきの変換結果に、原文に無い「その流派の創始者は常陸国の出身で…」が含まれる
- **THEN** お手本を LLM に渡さずに変換し直し、口語化テキストにはその結果が入る
- **AND** 画面に混入を見つけて変換し直した旨が表示され、`meta.json` に失敗の記録は足されない

#### Scenario: 引用が断片の境目で切れている
- **WHEN** 教育勅語の引用が断片の境目で切れ、「皇祖」が前の断片にある断片の訳に「皇室の祖先」が含まれる
- **THEN** お手本つきの結果は混入とみなされるが、お手本なしの結果は判定せずに採用され、正しい訳が口語化テキストに残る

#### Scenario: 原文が実際に引用している
- **WHEN** 原文の断片が「其ノ流祖ハ常陸國ノ人ニシテ…」を含み、変換結果に「常陸国」が含まれる
- **THEN** 混入とみなさず、お手本つきの結果をそのまま採用する

#### Scenario: 本物の租税の文
- **WHEN** 原文の断片が「日本國民ハ租税ヲ納ムルノ義務ヲ負フ。」で、変換結果に「日本の国民は」と「税金を納める義務」が含まれる
- **THEN** 原文に「税」があるので混入とみなさず、その結果を採用する

### Requirement: 変換し直さない設定では混入した断片を原文のまま残す
システムは `chunk.retry_without_examples` が false のとき、混入を見つけた断片を変換に失敗した断片と同じく原文のまま口語化テキストに残さなければならない（SHALL）。
その断片は失敗として数えて `meta.json` の `failed_chunks` に含め（SHALL）、画面には失敗の理由がお手本の混入であることを示さなければならない（SHALL）。
`chunk.on_error` が `abort` のときは、ほかの失敗と同じく変換全体を中止しなければならない（SHALL）。

#### Scenario: 変換し直さない
- **WHEN** `chunk.retry_without_examples = false` で、ある断片の変換結果に原文に無い「皇室の祖先が国を開いた」が含まれる
- **THEN** 変換し直さず、その断片は旧字体・カタカナの原文のまま口語化テキストに残り、ほかの断片は変換結果が入る
- **AND** 画面にはその断片の失敗の理由としてお手本の混入が示され、`meta.json` の `failed_chunks` は 1 になる

#### Scenario: 中止の方針
- **WHEN** `chunk.retry_without_examples = false` かつ `chunk.on_error = "abort"` で、ある断片の変換結果に混入がある
- **THEN** 口語化は中止され、ほかの失敗と同じく呼び出し元に失敗が伝わる

### Requirement: 生成の上限で途切れた断片を分けて変換し直す
システムは口語化した断片の応答が生成の上限で途切れたとき、その結果を採用してはならない（MUST NOT）。途中までの訳も採用してはならない（MUST NOT）。
その断片を原文に字を足さずに 2 つに分け、それぞれを変換し直した結果を順につないで採用しなければならない（SHALL）。
分けた片方がまた上限で途切れたら、その断片全体を変換に失敗した断片と同じく原文のまま残し、失敗として `meta.json` の `failed_chunks` に数えなければならない（SHALL）。
画面には、分けて変換し直したことと、失敗の理由が上限で途切れたことを示さなければならない（SHALL）。

#### Scenario: 分けて変換し直すと収まる
- **WHEN** 旧字体・カタカナ文語の 2,000 字の断片を口語化し、応答が生成の上限で途切れ、半分ずつ変換し直すとどちらも最後まで訳される
- **THEN** 口語化テキストのその位置には、半分ずつの訳が順につながって入り、途中で途切れた最初の訳は入らない
- **AND** 画面に分けて変換し直した旨が表示され、`meta.json` に失敗の記録は足されない

#### Scenario: 分けても途切れる
- **WHEN** ある断片の応答が生成の上限で途切れ、半分に分けた片方の応答もまた上限で途切れる
- **THEN** その断片は旧字体・カタカナの原文のまま口語化テキストに残り、ほかの断片には変換結果が入る
- **AND** 画面にはその断片の失敗の理由として生成の上限が示され、`meta.json` の `failed_chunks` は 1 になる

#### Scenario: 分けても原文に字を足さない
- **WHEN** 「。」で終わらない断片の応答が上限で途切れ、分けた両方とも変換に失敗して原文のまま残る
- **THEN** 口語化テキストのその位置は分ける前の断片の原文と一字も違わず、原文に無い「。」は付かない

#### Scenario: 中止の方針
- **WHEN** `chunk.on_error = "abort"` で、ある断片の応答が半分に分けても上限で途切れる
- **THEN** 口語化は中止され、ほかの失敗と同じく呼び出し元に失敗が伝わる

### Requirement: 連続して失敗したら残りの断片を変換せずに打ち切る
システムは口語化の断片が続けて設定 `chunk.abort_after_consecutive_failures`（既定 3）の数だけ失敗したとき、残りの断片を LLM に送ってはならない（MUST NOT）。
残りの断片は口語化テキストの同じ位置に原文のまま残し（SHALL）、変換に失敗した断片と合わせて `meta.json` の `failed_chunks` に数えなければならない（SHALL）。
設定が 0 なら打ち切ってはならない（MUST NOT）。お手本の混入・反復検知・生成の上限による失敗は数えず、打ち切り前の連続の数を戻してもならない（MUST NOT）。

#### Scenario: Ollama が固まって続けて失敗する
- **WHEN** 10 個の断片のうち 4〜6 個目が Ollama の応答待ちの時間切れで続けて失敗する
- **THEN** 7〜10 個目は LLM に送られずに原文のまま残り、1〜3 個目には変換結果が入る
- **AND** 画面に連続して失敗したため打ち切った旨と残りの断片の数が表示され、`meta.json` の `failed_chunks` は 7 になる

#### Scenario: 成功を挟めば打ち切らない
- **WHEN** 10 個の断片のうち 2・3 個目が時間切れで失敗し、4 個目が成功し、5・6 個目がまた時間切れで失敗する
- **THEN** 打ち切らずに 10 個目まで変換し、`meta.json` の `failed_chunks` は 4 になる

#### Scenario: 中身が原因の失敗は数えない
- **WHEN** 打ち切りの数が 3 で、続く 3 個の断片が、反復検知・生成の上限で途切れる・お手本の混入（変換し直さない設定）の順に失敗する
- **THEN** 打ち切らずに次の断片を変換する

#### Scenario: 数えない失敗を挟んでも連続は続く
- **WHEN** 打ち切りの数が 3 で、時間切れ・時間切れ・反復検知・時間切れの順に断片が失敗する
- **THEN** 4 個目の失敗（3 回目の時間切れ）で打ち切る

#### Scenario: 打ち切りを無効にする
- **WHEN** `chunk.abort_after_consecutive_failures = 0` で、すべての断片が時間切れで失敗する
- **THEN** 最後の断片まで LLM に送り、すべての断片が原文のまま残る
