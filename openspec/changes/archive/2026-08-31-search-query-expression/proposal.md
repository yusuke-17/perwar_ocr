## Why

現在のライブラリ検索は「スペース区切りのAND検索」しか表現できない。史料調査では
「関東か大阪のどちらかを含む」「震災を含むが横浜は除く」「原文にだけ残る語を狙い撃つ」
といった絞り込みが日常的に必要で、AND だけではノイズを手作業で読み飛ばすことになる。
FTS5 は OR / NOT / カラム指定をすでに備えているのに、CLI から届いていない。

あわせて検索結果の見え方も弱い。抜粋は16文字固定・`[ ]` の括弧強調で、長い文書では
一致箇所の前後がほとんど読めない。しかも `[ ]` は表示用の記号でありながら検索モジュール
内部に埋め込まれており、JSON 出力にも混入して機械処理を妨げている。

## What Changes

### 検索クエリの表現力

- 検索語を `OR` で繋いだとき、AND ではなく OR で絞り込む（**ORモード**）。
  検索語群のどこかに1つでも `OR` があれば、その群全体が OR 結合になる。
- `NOT` 以降に書いた語を**除外語**として扱う。除外語が複数あれば、そのいずれかを含む
  文書を結果から外す。
- `カラム名:語` の形で、一致対象を題名／口語化後テキスト／原文に限定できる。
  とくに `原文:` は「口語化で言い換えられて消えた語」を直接狙える。
- 演算子は記号ではなく `OR` / `NOT` のキーワードとする。`-除外` 形式は argparse が
  未知オプションとして解釈してしまい、`nargs="+"` の位置引数では受け取れないため採らない。
- 除外語だけのクエリは FTS5 で表現できないため、理由を示すエラーとする。

### 検索結果の見え方

- 抜粋の長さを設定と実行時オプションで変えられるようにする。
- 一致箇所の強調を ANSI カラーで行う。色の可否は既存の `--no-color` / `NO_COLOR` /
  非TTY / 設定 の判定に揃える。
- **BREAKING**（内部インタフェース）: `SearchHit.snippet` が持つ強調の表現を、
  表示用の `[ ]` から中立なマーカへ変える。text 出力は ANSI 色に、JSON 出力は
  マーカを取り除いた素の抜粋＋一致位置に変換する。JSON の `snippet` フィールドから
  `[ ]` が消えるため、この出力を機械処理していた利用側は影響を受ける。
- 一致の強さとして bm25 の生値は表示しない。trigram + 小規模・同ジャンルのコーパスでは
  頻出語のスコアが全件ゼロ付近に潰れて序列にならないことを実測で確認したため、
  代わりに**どの対象に何回一致したか**を提示する。

### 今回やらないこと（Non-goals）

- **日付ファセット**: `meta.json` の `created_at` は OCR を実行した日時であり、資料の
  年代ではない。研究者が求める「大正十二年の資料に絞る」は資料年代の獲得手段が
  未設計であり、独立した変更として扱う。
- **タグファセット**: `tags` は保存レコードに枠があるだけで入力導線もインデックスも
  存在しない。タグ付けのCLI編集（バックログ C4）が先行する必要がある。
- **索引スキーマの変更**: 本変更はクエリの組み立てと結果の見せ方だけを扱い、
  索引されるカラムや正規化規則には手を入れない。

## Capabilities

### New Capabilities

（なし）

### Modified Capabilities

- `library-search`: 検索クエリの表現力（OR / NOT / カラム指定）と、検索結果の抜粋・
  一致情報の提示に関する要件を追加・変更する。既存の「一致箇所の提示」要件は、
  抜粋の可変長化と強調表現の分離により内容が変わる。

## Impact

- `utils/library_search.py`
  - `_build_match_expr()` — 単純な分割＋AND連結から、演算子とカラム指定を解釈する
    クエリ解析へ置き換え
  - `search()` — 抜粋長を引数化、強調マーカの変更、一致回数の取得
  - `SearchHit` — 一致回数を保持するフィールドの追加
  - `QueryTooShortError` — 語の役割（検索語／除外語）が分かる文面へ
- `scripts/library.py`
  - `add_find_arguments()` — 抜粋長のオプション追加、ヘルプとエピローグの更新
  - `cmd_find()` — マーカ→ANSI色の変換、一致情報の表示
  - `_hit_to_dict()` — JSON 向けにマーカを除去し、一致位置を構造化
- `scripts/cli.py` — `_menu_search()` の入力の受け渡し（現在の `split()` / `join()`
  往復が演算子入りクエリを壊さないか要確認）とヘルプ文言
- `utils/config.py` — `[search]` に抜粋長の既定値を追加。`config.toml` にコメント追記
- 色判定ロジック — `scripts/diff_viewer.py` と `utils/progress.py` に同型の判定が
  すでに2箇所ある。3つ目を作らず共通化するか否かの判断が必要（design で扱う）
- `tests/` — 検索クエリ解析と出力整形のテストを追加
- `README.md` — 検索構文の説明
- 外部依存の追加なし。索引の作り直しも不要（`INDEX_SCHEMA_VERSION` は据え置き）
