## ADDED Requirements

### Requirement: 検索語のOR結合

利用者は、検索語のいずれか1つを含む文書を探せなければならない（SHALL）。
検索語群に OR 結合の指示が含まれる場合、システムはその群の全語を OR で結合しなければならず（SHALL）、
一部だけを AND、残りを OR とする混在解釈をしてはならない（SHALL NOT）。

OR 結合の指示が含まれない場合、システムは従来どおり全語を AND で結合しなければならない（SHALL）。

OR 結合される各語は、AND の場合と同一の正規化（旧字体→新字体・変体仮名→現代ひらがな・
歴史的仮名遣い→現代仮名遣い・カタカナ助詞→ひらがな）を経なければならない（SHALL）。

#### Scenario: いずれかの語を含む文書を探す

- **WHEN** 利用者が「関東地方」と「大阪府下」のいずれかを含む文書を OR 結合で検索する
- **THEN** どちらか一方だけを含む文書も結果に含まれる
- **AND** 両方を含む文書も結果に含まれる

#### Scenario: OR結合語も旧字体・歴史的仮名遣いを吸収する

- **WHEN** 一方の文書の原文が「關東地方」（旧字体）、他方が「大阪府下」で書かれている
- **AND** 利用者が現代表記の「関東地方」と「大阪府下」を OR 結合で検索する
- **THEN** 両方の文書が結果に含まれる

#### Scenario: OR結合の指示がない場合

- **WHEN** 利用者が OR 結合の指示なく複数の検索語を与える
- **THEN** 全語を含む文書だけが結果に含まれる（従来の AND 検索と同じ）

### Requirement: 検索語の除外

利用者は、特定の語を含む文書を結果から取り除けなければならない（SHALL）。
除外語が複数ある場合、システムはそのいずれか1つでも含む文書を結果から取り除かなければならない（SHALL）。

除外は文書全体を対象とし、題名・口語化後テキスト・原文のいずれに含まれていても
その文書を取り除かなければならない（SHALL）。

除外語は、検索語と同一の正規化を経なければならない（SHALL）。
原文が旧字体・歴史的仮名遣いで書かれていても、現代表記の除外語で取り除けなければならない（SHALL）。

除外語だけを与えられた場合、システムは結果を返さず、検索語が必要である旨を利用者に伝えなければならない（SHALL）。

#### Scenario: 特定の語を含む文書を除く

- **WHEN** 利用者が「震災」を検索し、「大阪府下」を除外語に指定する
- **THEN** 「震災」を含み「大阪府下」を含まない文書だけが結果に含まれる

#### Scenario: 除外語が複数ある

- **WHEN** 利用者が「震災」を検索し、「大阪府下」と「横浜港」を除外語に指定する
- **THEN** どちらか一方でも含む文書は結果から取り除かれる

#### Scenario: 原文にだけ除外語がある文書

- **WHEN** 除外語「罹災者」が、ある文書の原文にのみ存在し、口語化後テキストには「被災者」として現れる
- **AND** 利用者がその語を除外語に指定して検索する
- **THEN** その文書は結果から取り除かれる

#### Scenario: 旧字体の原文を現代表記の除外語で取り除く

- **WHEN** ある文書の原文に「橫濱港」（旧字体）とある
- **AND** 利用者が現代表記の「横浜港」を除外語に指定する
- **THEN** その文書は結果から取り除かれる

#### Scenario: 除外語だけのクエリ

- **WHEN** 利用者が検索語を与えず除外語だけを指定する
- **THEN** 検索は実行されず、検索語が必要である旨が示される

### Requirement: 一致対象の限定

利用者は、語が一致する対象を題名・口語化後テキスト・原文のいずれかに限定できなければならない（SHALL）。
限定された語は、指定された対象に含まれる場合にのみ一致とみなされなければならない（SHALL）。

対象を限定した語は、限定しない語および除外語と同一の検索式の中で併用できなければならない（SHALL）。

限定に使える対象名は、システムが定める既知の名称に限らなければならない（SHALL）。
既知でない対象名を与えられた場合、システムは利用可能な対象名を示すエラーを返さなければならない（SHALL）。

限定された語も、限定しない語と同一の正規化を経なければならない（SHALL）。

#### Scenario: 原文にだけ残る語を狙って検索する

- **WHEN** ある文書の原文に「罹災者」とあり、口語化後テキストでは「被災者」に置き換わっている
- **AND** 利用者が対象を原文に限定して「罹災者」を検索する
- **THEN** その文書が結果に含まれる

#### Scenario: 限定した対象に無い語は一致しない

- **WHEN** ある語が口語化後テキストにのみ存在する
- **AND** 利用者が対象を原文に限定してその語を検索する
- **THEN** その文書は結果に含まれない

#### Scenario: 題名に限定して検索する

- **WHEN** 題名が「關東大震災ノ記錄」（旧字体）である文書がある
- **AND** 利用者が対象を題名に限定して現代表記の「関東大震災」を検索する
- **THEN** その文書が結果に含まれる

#### Scenario: 限定した語と限定しない語の併用

- **WHEN** 利用者が対象を原文に限定した語と、限定しない語を同時に指定する
- **THEN** 両方の条件を満たす文書だけが結果に含まれる

#### Scenario: 未知の対象名

- **WHEN** 利用者がシステムの知らない対象名で限定を指定する
- **THEN** 検索は実行されず、利用可能な対象名が示される

### Requirement: 検索できない語の通知

いずれかの語が、部分一致検索に必要な最小文字数（正規化後）に満たない場合、
システムは検索を実行せず、その語を検索できない旨を利用者に伝えなければならない（SHALL）。

通知は、対象の語がどの役割（検索語・除外語・対象を限定した語）で与えられたかを
利用者が判別できる形でなければならない（SHALL）。

文字数の判定は正規化の**後**に行わなければならない（SHALL）。
歴史的仮名遣いの変換や拗音の縮約により、正規化で字数が減ることがあるためである。

#### Scenario: 短い除外語

- **WHEN** 利用者が最小文字数に満たない語を除外語に指定する
- **THEN** 検索は実行されず、その語が除外語として検索できない旨が示される

#### Scenario: 正規化で字数が減って最小文字数を割る語

- **WHEN** 利用者が与えた語が、歴史的仮名遣いの変換により正規化後に最小文字数を下回る
- **THEN** 検索は実行されず、正規化後の語が示された上で検索できない旨が伝えられる

### Requirement: 抜粋の長さの調整

検索結果の抜粋の長さは、利用者が実行時に指定できなければならない（SHALL）。
指定がない場合は、設定で定められた既定の長さを用いなければならない（SHALL）。

システムは、抜粋の長さとして安全に扱える上限を持たなければならず（SHALL）、
上限を超える指定は上限に丸めなければならない（SHALL）。
零以下の長さを指定された場合は、その旨を伝えて検索を実行してはならない（SHALL NOT）。

#### Scenario: 長い抜粋を求める

- **WHEN** 利用者が既定より長い抜粋を指定して検索する
- **THEN** 一致箇所の前後がより広く含まれた抜粋が表示される

#### Scenario: 上限を超える長さの指定

- **WHEN** 利用者がシステムの上限を超える抜粋の長さを指定する
- **THEN** 検索は実行され、抜粋は上限の長さで生成される

#### Scenario: 不正な長さの指定

- **WHEN** 利用者が零以下の抜粋の長さを指定する
- **THEN** 検索は実行されず、長さが不正である旨が示される

### Requirement: 一致の量の提示

各検索結果は、対象（題名／口語化後テキスト／原文）ごとに検索語が何箇所一致したかを
保持しなければならない（SHALL）。この情報は JSON 形式の出力に含めなければならない（SHALL）。

システムは、検索結果の並び順を決める内部の評価値を、利用者向けの出力に表示してはならない（SHALL NOT）。
語彙の偏った小規模な資料集では、この評価値が全件で同一に潰れて序列を成さないためである。

#### Scenario: 一致箇所の多い文書を見分ける

- **WHEN** 検索語が、ある文書の原文に複数箇所一致する
- **THEN** その結果には原文における一致箇所の数が含まれる

#### Scenario: 一致しなかった対象

- **WHEN** 検索語が題名に一致しない
- **THEN** その結果の題名についての一致箇所数は零である

#### Scenario: JSON 出力への一致数の反映

- **WHEN** JSON 形式で検索結果を出力する
- **THEN** 各件に対象ごとの一致箇所数が含まれる

## MODIFIED Requirements

### Requirement: 一致箇所の提示

検索結果の抜粋（スニペット）は、**実際に検索語が一致したテキスト**から生成されなければならない（SHALL）。
複数のテキストが一致した場合は、最もよく一致したものから生成する。

各検索結果は、どの対象（題名／口語化後テキスト／原文）に一致したかを保持しなければならず（SHALL）、
JSON 形式の出力にもその情報を含めなければならない（SHALL）。

原文にのみ一致し口語化後テキストに一致しなかった場合、テキスト形式の出力は
その事実を利用者が判別できる形で示さなければならない（SHALL）。
これは「口語化で語が失われた箇所」を示す、史料調査上の重要な手がかりである。

抜粋における一致箇所の強調は、出力形式から独立して保持されなければならない（SHALL）。
表示用の記号を抜粋の本体に埋め込んでは**ならない**（SHALL NOT）。
テキスト形式の出力は一致箇所を色で強調しなければならず（SHALL）、
JSON 形式の出力は強調のための装飾を含まない素の抜粋と、一致箇所の位置を
機械処理できる形で持たなければならない（SHALL）。

色による強調は、利用者の明示的な指定・環境変数・出力先が端末でないこと・設定のいずれかに
より無効化されなければならず（SHALL）、無効時も抜粋の本文は欠落なく出力されなければならない（SHALL）。

除外語は抜粋の強調対象としてはならない（SHALL NOT）。除外語は文書に含まれないためである。

#### Scenario: 原文だけに一致した結果の抜粋

- **WHEN** 検索語が原文にのみ一致する
- **THEN** 抜粋は原文から生成され、一致箇所が強調される
- **AND** 原文にのみ一致した旨が結果に示される

#### Scenario: 口語化後テキストに一致した結果の抜粋

- **WHEN** 検索語が口語化後テキストに一致する
- **THEN** 抜粋は口語化後テキストから生成される

#### Scenario: JSON 出力

- **WHEN** JSON 形式で検索結果を出力する
- **THEN** 各件に一致した対象の一覧が含まれる
- **AND** 抜粋には表示用の装飾記号が含まれない
- **AND** 一致箇所の位置が機械処理できる形で含まれる

#### Scenario: 色が使えない出力先

- **WHEN** 検索結果をファイルへリダイレクトする、または色を無効にして実行する
- **THEN** 抜粋は色の制御文字を含まない素のテキストとして出力される
- **AND** 抜粋の本文は色付きの場合と同一である

#### Scenario: 抜粋本文に含まれる記号

- **WHEN** 一致した文書の本文が角括弧などの記号を含む
- **THEN** その記号は本文の一部として出力され、強調の指標とは区別できる
