## Purpose

蓄積済みの戦前文書ライブラリを、完全ローカルの全文検索で引けるようにする能力。
旧字体・カタカナ仮名遣い・歴史的仮名遣いで書かれた原文と、口語化された現代文の
どちらの語からでも同じ文書に辿り着けることを保証し、史料調査での取りこぼしを防ぐ。

## ADDED Requirements

### Requirement: 原文の語による検索

検索インデックスは、口語化後テキストに加えて、**OCR原文を正規化したテキスト**を
索引対象に含めなければならない（SHALL）。正規化とは、旧字体→新字体・変体仮名→現代ひらがな・
歴史的仮名遣い→現代仮名遣い・カタカナ助詞→ひらがなを含む、検索クエリ側と同じ表記への揃え直しを指す。

これにより、口語化の過程で言い換えられた語（原文にのみ存在する語）でも、
その語を含む文書が検索結果に現れなければならない（SHALL）。

#### Scenario: 口語化で言い換えられた語で検索する

- **WHEN** 原文に「罹災者」とあり、口語化後テキストでは「被災者」に置き換わっている文書がある
- **AND** 利用者が「罹災者」で検索する
- **THEN** その文書が検索結果に含まれる

#### Scenario: 口語化後にしか無い語で検索する

- **WHEN** 原文には無いが口語化後テキストに現れる語で検索する
- **THEN** 従来どおりその文書が検索結果に含まれる（既存の再現率を落とさない）

#### Scenario: 旧字体・歴史的仮名遣いの原文を現代表記のクエリで引く

- **WHEN** 原文が「關東大震災」「けふ」のように旧字体・歴史的仮名遣いで書かれている
- **AND** 利用者が現代表記の「関東大震災」「きょう」で検索する
- **THEN** その文書が検索結果に含まれる

#### Scenario: 原文が読めない文書

- **WHEN** 文書フォルダに原文テキストが存在しない、または読み取りに失敗する
- **THEN** その文書は原文カラムを空として索引され、口語化後テキストによる検索は従来どおり機能する
- **AND** 文書そのものが索引から除外されることはない

### Requirement: 題名の表記揺れ吸収

索引される題名は、本文と同じ正規化を経ていなければならない（SHALL）。
題名は生のOCR出力から切り出されるため、旧字体・歴史的仮名遣いを含みうる。

表示される題名は正規化前の元の文字列を保たなければならない（SHALL）。
索引は照合のためのものであり、利用者に見せる題名を書き換えてはならない。

#### Scenario: 旧字体の題名を現代表記で引く

- **WHEN** 題名が「關東大震災ノ記錄」（旧字体）である文書がある
- **AND** 利用者が「関東大震災」で検索する
- **THEN** その文書が検索結果に含まれる
- **AND** 表示される題名は元の「關東大震災ノ記錄」のままである

### Requirement: 一致箇所の提示

検索結果の抜粋（スニペット）は、**実際に検索語が一致したテキスト**から生成されなければならない（SHALL）。
複数のテキストが一致した場合は、最もよく一致したものから生成する。

各検索結果は、どの対象（題名／口語化後テキスト／原文）に一致したかを保持しなければならず（SHALL）、
JSON 形式の出力にもその情報を含めなければならない（SHALL）。

原文にのみ一致し口語化後テキストに一致しなかった場合、テキスト形式の出力は
その事実を利用者が判別できる形で示さなければならない（SHALL）。
これは「口語化で語が失われた箇所」を示す、史料調査上の重要な手がかりである。

#### Scenario: 原文だけに一致した結果の抜粋

- **WHEN** 検索語が原文にのみ一致する
- **THEN** 抜粋は原文から生成され、一致箇所が強調される
- **AND** 原文にのみ一致した旨が結果に示される

#### Scenario: 口語化後テキストに一致した結果の抜粋

- **WHEN** 検索語が口語化後テキストに一致する
- **THEN** 抜粋は口語化後テキストから生成される

#### Scenario: JSON 出力

- **WHEN** JSON 形式で検索結果を出力する
- **THEN** 各件に一致した対象の一覧が含まれる

### Requirement: 索引の変更検知

差分更新は、索引の入力となる**すべてのファイル**の変更を検知しなければならない（SHALL）。
すなわち、メタデータ・口語化後テキスト・OCR原文のいずれか1つでも更新されていれば、
その文書を再索引しなければならない（SHALL）。

いずれも更新されていない文書は再索引せず、処理を省略してよい（MAY）。

#### Scenario: 口語化後テキストの手修正

- **WHEN** 利用者が誤変換を直すため口語化後テキストを手で編集する
- **AND** 索引の差分更新を実行する
- **THEN** その文書が再索引され、修正後の本文で検索できる
- **AND** 修正前の本文では検索されない

#### Scenario: OCR原文の手修正

- **WHEN** 利用者がOCRの誤読を直すため原文テキストを手で編集する
- **AND** 索引の差分更新を実行する
- **THEN** その文書が再索引され、修正後の原文の語で検索できる

#### Scenario: 変更のない文書

- **WHEN** 索引の入力ファイルがいずれも更新されていない文書がある
- **AND** 索引の差分更新を実行する
- **THEN** その文書は再索引されず、更新件数にも数えられない

### Requirement: 索引形式の変更への追従

索引は自身の形式（スキーマ）の版を保持しなければならない（SHALL）。
保存されている索引の版が現在の実装と異なる場合、システムは索引を自動的に作り直さなければならず（SHALL）、
再構築を行った旨を利用者に伝えなければならない（SHALL）。

利用者に手動の再構築操作を要求してはならない（SHALL NOT）。
再構築は索引のみを対象とし、ライブラリ内の資料ファイルを変更してはならない（SHALL NOT）。

#### Scenario: 旧形式の索引で検索する

- **WHEN** 旧形式で作られた索引が残っている状態で検索を実行する
- **THEN** 索引が自動的に作り直される旨が表示される
- **AND** 再構築後の索引で検索が実行され、正しい結果が返る

#### Scenario: 再構築後の資料の保全

- **WHEN** 索引が自動的に作り直される
- **THEN** ライブラリ内の資料ファイル（原文・口語化後テキスト・メタデータ・画像）は一切変更されない

### Requirement: 完全ローカル動作の維持

索引の構築・更新・検索は、資料の内容を外部へ送信することなく完結しなければならない（SHALL）。
原文の正規化は、外部サービスやLLMを介さない決定的な変換でなければならない（SHALL）。

#### Scenario: 索引更新時の外部通信

- **WHEN** 索引の構築・更新・検索を実行する
- **THEN** 資料内容を含む外部通信は一切発生しない

#### Scenario: 正規化の決定性

- **WHEN** 同じ原文に対して索引更新を2回実行する
- **THEN** 索引される正規化済み原文は毎回同一である
