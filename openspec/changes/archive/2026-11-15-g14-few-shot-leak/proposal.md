# Proposal

## Why

口語化では LLM に few-shot のお手本（`FEW_SHOT_EXAMPLES` の 3 例）を「過去の会話」として渡している。モデルがお手本までを本文と取り違え、お手本の入力を訳し直した文（「その流派の開祖は常陸国…」「日本の国民は…税金を納める義務…」）を口語化の結果に混ぜることがある。
2026-11-03 の B3 の実機確認で見つかり、同じチャンクを 6 回変換すると 3 回混入した。原文に無い文がエラーも警告もなく記録に残り、全文検索にも載るので、「静かに壊れる」G 系の不具合として最優先で止める。

## What Changes

- 口語化した 1 チャンクの結果に、**お手本由来の語が含まれていて、かつそのチャンクの原文に対応する語が無い**とき、その結果を「お手本の混入」として採用しない
- 混入を見つけたら、そのチャンクを**お手本を渡さずに 1 回変換し直し**、その結果を採用する（新しい設定 `chunk.retry_without_examples`、既定 true）。お手本が無ければ混入は起きようがないので、お手本なしの結果は判定しない。最初の変換はこれまでどおりお手本つきで行い、通常のチャンクのプロンプトは変えない
  - 当初はお手本つきのまま変換し直す計画だったが、実機の確認で、話題がお手本と同じ資料（流派の由来を記した文書）では 3 回とも混入し、再試行では直らなかった。お手本なしでは混入せずに最後まで訳せた（design D2）
- 変換し直したときは、画面に 1 行知らせるだけで `meta.json` には何も足さない
- `retry_without_examples = false` のときは、混入したチャンクを**変換に失敗したチャンクと同じ扱い**にする。原文のまま残し、画面に理由を出し、`meta.json` の `failed_chunks` に数える（既存の失敗時の処理に合流させ、新しい保存形式は作らない）
- 原文が憲法・教育勅語などを実際に引用している場合は、原文に対応する語があるので混入とみなさない
- プロンプトの文面（`SYSTEM_PROMPT`・`FEW_SHOT_EXAMPLES`）は変えない。お手本の差し替えなど、最初の変換で混入の頻度そのものを下げる工夫は、この変更の範囲外とする

## Capabilities

### New Capabilities

（なし）

### Modified Capabilities

- `text-modernization`: 「口語化の結果に few-shot のお手本の文を残さない」要件を追加する（検出・お手本なしでの変換し直し・変換し直さない設定では原文のまま残す）

## Impact

- `utils/text_modernizer.py`: お手本ごとの目印の語、混入の判定、お手本を外したメッセージの組み立て、チャンク単位の変換し直し、変換し直さない設定のときの専用の例外
- `utils/config.py`: `_DEFAULTS` の `chunk` に `retry_without_examples` を追加
- `config.toml`: `[chunk]` のコメントに `on_error` と `retry_without_examples` の説明を追加（値は既定のまま）
- テスト: `tests/test_text_modernizer.py` と `tests/test_modernize_resilience.py` に、LLM 呼び出しを差し替えた検証を追加。Ollama は不要
- `prewar ocr` と `prewar fix` の両方に効く（どちらも `modernize_detailed()` を通るため）。呼び出し側・`library_writer.py`・`meta.json` の形は変えない
- 依存の追加なし。検索索引の版（`INDEX_SCHEMA_VERSION`）は上げない（既存の記録は作り直さない）
- 処理時間: 混入したチャンクだけ LLM の呼び出しが 1 回増える
