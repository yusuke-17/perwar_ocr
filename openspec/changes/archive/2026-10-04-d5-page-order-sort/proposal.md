## Why

複数の画像を1件の文書に結合するとき、ファイル名を文字列として並べているため、0埋めのない連番
（`1.png, 2.png, …, 10.png`）は `1, 10, 11, …, 19, 2, 20, …` の順になる。実物の `input/1.png`〜`32.png` では
32枚中31枚の位置がずれ、エラーも警告も出ないまま、ページが入れ替わった文書が口語体に変換・保存される。
B3（ページ境界の連結）や G11（失敗ページの目印）で境界を整えても、ページ順が誤っていれば文書全体が無意味になるため、
それらより先に直す必要がある。調査の詳細は `survey/d5-page-order-survey.md`。

## What Changes

- **ページ順を自然順にする**: ファイル名の数字部分を数値として比べる（`2.png` は `10.png` より前）。
  フォルダ指定、対話メニューの複数選択、画像の一覧表示のすべてに適用する。外部依存は追加しない。
- **並び順を処理前に表示する**: 複数枚を結合する前に、番号付きの一覧で並び順を表示する
  （現在の `対象: a.png, b.png, …` の1行表示を置き換える）。
- **名前順と更新日時順の食い違いを警告する**: 名前順で結合するとき、ファイルの更新日時の順と食い違えば警告する。
  フォルダ指定（非対話）では警告を表示して続行し、終了コードは変えない。
  対話メニューでは「このまま進む / 更新日時順にする / やめる」を選べるようにする。
  撮りため（`shoot`）と、画像ごとの別記録（`--separate`）は警告の対象外。
- **並べ方を指定できるようにする**: `--order name|mtime` と `config.toml` の `[batch] order`（既定は `name`）。
- **画像の列挙を1箇所にまとめる**: 3箇所に同じ形で書かれている列挙と並べ替えを1つの関数にまとめ、あわせて次を直す。
  - OCR が対応している `.tif` / `.webp` が、フォルダ処理と一覧で黙って無視される（そのページだけ抜ける）
  - 隠しファイル（`._1.png` など）が画像として拾われる
  - 画像のような名前のフォルダ（`x.png/`）が画像として拾われる
- **撮りためが1000枚目から崩れる問題を直す**: 撮影済みリストを文字列順に並べ直している処理をやめ、撮った順のまま使う。

破壊的な変更はない。0埋めの名前（`p001.png` 形式）の並び順は変わらない。0埋めのない名前は並び順が変わるが、
これは誤りの修正である。`library/` の既存の記録には影響しない（現在0件）。

スコープ外: 並び順の手動の入れ替え、meta.json への元ファイル名の記録、英語の AM/PM 表記など
名前から順序が決まらない形式への個別対応、EXIF の撮影日時の利用。

## Capabilities

### New Capabilities

なし

### Modified Capabilities

- `ocr-pipeline`: 「フォルダの一括処理」の並び順の定義と対象ファイルの範囲を改める。
  ページ順の決定（自然順）、並べ方の指定、並び順の表示、食い違いの警告の要件を追加する。

## Impact

- コード
  - `utils/`（新規モジュール）: 自然順のキー、画像の列挙、並べ替え、食い違いの検知
  - `scripts/ocr_vision_llm.py`: 列挙・並べ替えの3箇所の置き換え、`--order` の追加、並び順の表示、警告と対話での選択
  - `utils/screen_capture.py`: 撮影済みリストの並べ直しを削除
  - `scripts/clean.py`: 画像拡張子の定義を共通のものに置き換え
  - `utils/config.py` / `config.toml`: `batch.order` の追加
- 仕様: `openspec/specs/ocr-pipeline/spec.md`
- テスト: 自然順のキー、列挙、並べ方の指定、警告、対話での選択のテストを追加。
  `tests/test_ocr_pipeline.py` の `対象:` 行を確認しているテストと、`tests/test_cli.py` の引数一覧を更新
- ドキュメント: `README.md`、`PROGRESS.md`、`plan/improvement-ideas.md`
- 依存パッケージ: 追加・削除なし
- 外部送信: なし（ファイル名と更新日時をローカルで読むだけ）
