## Context

動機は proposal.md の Why、調査の全体は `survey/d5-page-order-survey.md` を参照。ここでは設計に効く現状だけを挙げる。

- 画像の列挙と並べ替えが `scripts/ocr_vision_llm.py` の3箇所（`:167` 1枚選択の一覧、`:210`/`:229` 複数選択、`:746` フォルダ）に
  同じ形で書かれており、すべて `sorted(Path のリスト)`（文字列順）。
- 画像拡張子の定義が3つある。`ocr_vision_llm.IMAGE_EXTENSIONS` と `clean.IMAGE_EXTENSIONS` は5種類、
  OCR クライアントの `ollama_client.SUPPORTED_EXTENSIONS` は `.webp` と `.tif` を加えた7種類。
- 複数ページを1文書にする入口は「フォルダ指定」「対話メニューの複数選択」「撮りため（`shoot`）」の3つ。
  撮りためは撮影後に `process_folder` を呼び、フォルダを列挙し直している。
- 設定の解決は `_batch_policy` が「CLI フラグ > `config.toml` > 既定値」で行っている（`on_page_error`）。
- 対話メニューは `cli._defaults_for` で引数の既定値を作るため、引数を足せばメニュー経路にも自動で届く。
- `questionary.checkbox` はチェックした順を返さない（表示順で返す）。

## Goals / Non-Goals

**Goals:**

- 列挙・並べ替え・食い違い検知を、画面入出力を持たない関数として1つのモジュールにまとめ、Ollama も対話も無しでテストできるようにする。
- 入口ごとの振る舞い（警告するか、選ばせるか）を1つの表で決め、実装とテストをその表に対応させる。
- 0埋めの名前（`pNNN`）の既存テストを変更なしで通す。

**Non-Goals:**

- Finder の並び順との完全一致（OS の比較規則の再現には別ライブラリが要る）。
- 漢数字、英語の AM/PM 表記、iPhone の連番の巻き戻りを名前から正しく並べること。これらは警告と更新日時順で受け止める。
- 対応していない形式（`.heic`、`.jp2` など）が混ざったときの通知。今回は対応形式の定義をそろえるところまで。
- 並び順の手動の入れ替え、meta.json への元ファイル名の記録。

## Decisions

### D1. 自然順のキーは自作する（`natsort` を使わない）

必要な規則が少なく、標準ライブラリ（`re`、`unicodedata`）だけで15行程度に収まる。
`natsort` は最新版が2023年のリリースで、対応表記が Python 3.11 まで。G8 で依存を減らした直後でもある。

- 代替案: `natsort` を追加 → 規則の調整（拡張子の扱い、同値の決め方）が結局必要で、依存を増やす利点が小さい。

### D2. キーの作り方

```
(トークン列, 拡張子の小文字, 元のファイル名)
```

- **拡張子を除いた名前（stem）で比べる**。拡張子込みだと `X (2).png` が `X.png` より前になる（空白が `.` より前のため）。
- stem を **NFKC で正規化し `casefold()`** してから分割する。NFKC は全角英数字を半角に、濁点の2通りの表し方を1つに、
  AM/PM の前の特殊な空白（U+202F）を通常の空白にそろえる。
- `re.split(r"(\d+)", …)` で分割する。結果は必ず「文字・数字・文字…」の交互になるので、位置で数字と判断する。
  `isdigit()` では判定しない（`'²'.isdigit()` は真だが `int('²')` は失敗する）。
- 各トークンは `(種別, 値, 桁数)` の組にする。文字は `(0, 文字列, 0)`、数字は `(1, 数値, 桁数)`。
  種別を先頭に置くことで、文字と数値が比較されて TypeError になることを構造的に防ぐ。
- 数値が同じ名前（`1.png` と `01.png`、全角と半角）は、桁数 → 拡張子 → 元のファイル名の順で決める。
  最後に元のファイル名を置くので、同じ集合なら必ず同じ順になる。
- 代替案: 名前全体（拡張子込み）で比べる → ` (2)` の順が逆になるため不採用。
  NFC で正規化 → 全角英字や U+202F がそろわないため NFKC を採用。

### D3. 列挙・並べ替え・検知を `utils/page_order.py` にまとめる

PJ 固有の処理なので `utils/` に置く（`pkg/senzen_word/` には入れない）。画面出力と対話は持たせない。

| 関数（仮名） | 役割 |
|---|---|
| `natural_key(path)` | D2 のキー |
| `list_images(folder)` | フォルダ直下の画像を自然順で返す。通常のファイルだけ、名前が `.` で始まるものは除く、拡張子は D4 の集合 |
| `sort_pages(paths, order)` | `"name"` は自然順、`"mtime"` は `(st_mtime_ns, 自然順のキー)` の順 |
| `first_mismatch(paths)` | 自然順と更新日時順を比べ、最初に食い違う位置と両方の画像を返す。食い違いが無ければ `None` |

`ocr_vision_llm.py` の3箇所と `load_folder_images` は `list_images` を呼ぶ形に置き換える。
画面出力（一覧、警告）と対話での選択は、これまでどおり `scripts/ocr_vision_llm.py` 側に置く。

- 代替案: `ocr_vision_llm.py` の中に関数を足す → 867行あるファイルがさらに膨らみ、`clean.py` から拡張子の定義を共有しにくい。

### D4. 画像拡張子の正は `ollama_client.SUPPORTED_EXTENSIONS` にする

OCR が実際に受け付ける集合が正であり、列挙側がそれより狭いと「対応しているのに黙って無視される」が起きる。
`ocr_vision_llm.IMAGE_EXTENSIONS` と `clean.IMAGE_EXTENSIONS` は削除し、`list_images` と `clean.py` は正の集合を参照する。
これで `.tif` と `.webp` がフォルダ処理・一覧・データ整理の対象に加わる。
前処理（OpenCV）が両形式を読めることはテストで確かめる。

- 代替案: `page_order.py` に新しい定義を置き、OCR クライアントがそれを参照する → OCR クライアントが上位の都合に依存する向きになるため不採用。

### D5. 並べ方の解決は既存の `_batch_policy` と同じ形にする

- 引数: `--order`、`choices=["name", "mtime"]`、`default=None`（未指定を区別するため）。
- 設定: `_DEFAULTS` の `batch.order = "name"`。`config.toml` のコメント例にも追記する。
- 優先順: CLI フラグ > `config.toml` > 既定値。
- 設定ファイルの値が `name` / `mtime` 以外なら、使える値を示すエラーを表示して終了コード 1 で終わる。
  ページ順は結果を左右するので、黙って既定値に戻すことはしない。
- 引数の未知の値は argparse が弾く（既存の `--on-page-error` と同じ）。

### D6. 更新日時は `st_mtime_ns` を使う

- 作成日時（`st_birthtime`）は使わない。Linux に属性が無く、`st_birthtime_ns` は Windows 専用で macOS では AttributeError になる。
- 秒未満まで持つ `st_mtime_ns` を使い、同値は自然順のキーで決める。
  これにより、zip 展開などで更新日時がそろっている場合は「食い違いなし」になる。
- EXIF は読まない（Pillow は G8 で削除済み、OpenCV は EXIF を読めない）。

### D7. 入口ごとの振る舞い

| 入口 | 並べ方 | 番号付き一覧 | 食い違いの検知 |
|---|---|---|---|
| フォルダ指定（結合） | 指定に従う | 表示 | 名前順のときだけ検知。警告を表示して続行。終了コードは変えない |
| フォルダ指定（`--separate`） | 指定に従う | 表示しない（既存の `i/N: 名前` の表示がある） | しない（結合しないので順序の誤りが文書を壊さない） |
| 対話メニューの複数選択 | 指定に従う | 表示 | 名前順のときだけ検知。3択で選ばせる |
| 対話メニューの1枚選択 | — | — | しない（一覧の表示順だけ自然順にする） |
| 撮りため（`shoot`） | 常に撮った順 | 表示 | しない |
| 画像1枚の指定 | — | 表示しない | しない |

- 「非対話」は「フォルダ指定」と同じ意味で扱う。端末かどうか（TTY）の判定はしない。
  フォルダ指定は端末から実行しても選択を挟まない（スクリプトから呼んでも止まらないようにするため）。
- **更新日時順を指定したときは検知しない**。名前が当てにならないから選んだはずで、毎回の警告は雑音になる。
- **撮りため**は、撮影済みリスト（撮った順）をそのまま処理に渡し、フォルダを列挙し直さない。
  `process_folder` に画像リストを直接渡せる口を足し、渡されたときは並べ替えも検知もしない。
  `screen_capture.shoot_session` の末尾の `sorted(captured)` は外す（1000枚目から崩れる原因）。
  `--no-run` で撮影だけして後から `prewar ocr <セッションフォルダ>` する場合は、通常のフォルダ指定として扱う。
- 対話メニューで「やめる」を選んだときは、既存の「選択をキャンセルした」ときと同じ経路（`None` を返し終了コード 1）に乗せる。
- 対話メニューで更新日時順を選んだときは、並べ替え後の一覧をもう一度表示する。

### D8. 表示

現在 `process_batch` が出している `対象: a.png, b.png, …` の1行を、番号付き一覧に置き換える。

```
処理モード: 複数画像（32枚）
並び順: ファイル名順
   1. 1.png
   2. 2.png
   …
```

- 一覧と警告は、順序を決める場所（フォルダ指定の入口と、対話の複数選択の直後）で出す。
  対話では選択肢を出す前に一覧が見えている必要があるため、`process_batch` の中では遅い。
- 警告は一覧の後に出し、「最初に食い違う位置」「その位置で名前順と更新日時順がそれぞれ指す画像」
  「切り替え方法（`--order mtime`）」「コピーなどで日時が変わっているなら名前順が正しい」を示す。
  両方の順を全件並べることはしない（32枚で60行を超え、読まれなくなる）。
- `tests/test_ocr_pipeline.py:463` が `対象:` 行を確認しているので、新しい表示に合わせて更新する。

### D9. テストの方針

- `utils/page_order.py` は純粋な関数なので、`tmp_path` に空ファイルを作って確かめる。更新日時は `os.utime` で設定する。
- パイプラインは既存のフェイク（`tests/fakes.py`）を使い、結合後の本文の順で確かめる。
  本文は既存テストと同じく旧字体・カタカナ書きの文字列を使う。
- 対話の選択は `questionary` を差し替えて確かめる（既存の `process_*` と同様、選択部分を薄く保つ）。

## Risks / Trade-offs

- [コピーで更新日時が変わったフォルダで誤警告が出る]（`cp` は文字列順にコピーするため、更新日時順が `1, 10, 11, …` になる）
  → 警告文に「コピーなどで日時が変わっている場合は名前順が正しい」と書く。フォルダ指定では処理を止めない。
- [数百枚の文書で一覧が長くなる] → 確認できることを優先して全件表示する。実運用で邪魔なら、後から省略表示を足せる（仕様の変更は不要な範囲で調整する）。
- [`.tif` / `.webp` が新たに拾われ、同じフォルダの処理結果が変わる] → これまで黙って抜けていたページが入るので、変化は修正の方向。README に明記する。
- [複数ページの TIFF は先頭ページしか読まれない可能性がある] → 今回は対象外。テストで1ページの TIFF が通ることだけ確かめ、複数ページ TIFF は README の注意書きにとどめる。
- [更新日時順で直せない場合がある]（名前も日時も当てにならない） → 今回は手動の入れ替えを含めない。利用者がファイル名を付け直す運用で対応し、必要になったら別の変更で扱う。
- [自然順で順序が変わる既存の運用] → 0埋めの名前は変わらない。0埋めなしの名前は変わるが、従来が誤り。`library/` は0件で、既存の記録は無い。

## Migration Plan

データの移行は不要。既存の記録の形式（meta.json、`source_NN`）は変えない。
元に戻す場合は、この変更のコミットを取り消すだけでよい（設定キー `batch.order` は未知のキーとして無視される）。
